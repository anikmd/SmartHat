# Contributing to SmartHat

Thank you for helping improve SmartHat.

## Before contributing

- Read the README and hardware documentation.
- Do not commit passwords, API keys, SIM credentials, phone numbers, or other private data.
- Do not describe unverified behavior as a safety guarantee.
- Test hardware changes on a controlled prototype before documenting them as working.

## Pull requests

1. Create a focused branch from `main`.
2. Explain what changed and why.
3. Include test conditions and results for hardware/firmware changes.
4. Update the README or diagrams when behavior or wiring changes.
5. Keep commits focused and descriptive.

## Hardware changes

When changing components or wiring, document:

- Component name and exact model where known
- Operating voltage/current requirements
- Pin mapping
- Expected behavior
- Test procedure
- Known limitations

## Reporting issues

Use GitHub Issues for reproducible bugs, documentation errors, and feature proposals. Include the board/module versions, observed behavior, expected behavior, and relevant test conditions.
